# A retrospective presents one flat, tagged list ranked by occurrences, with unnumbered tails

Robin presents the patterns a retrospective found as one flat numbered list, so
the human can say yes to each one. Settled by the grilling mc-4ryp.6.7, on the
outputs of the reading prototype (ADR 0277
(mugicrew-a-retrospective-reads-digests-in-turn…)).

1. **Header.** One line: how many sessions were read and how many had a
   transcript, e.g. `26 sessions read, 24 with a transcript`.
2. **Flat, tagged, ranked.** Patterns are numbered in one list, most sessions
   first. Each title line has a kind tag (`[harness]`, `[process]`, `[code]`),
   the count `(N sessions)`, and when it applies `overlaps M` or
   `regression of <closed bead title>`. The tag is only for reading. Context
   and priority are still set at triage. There is no cap on the list's length.
3. **Recurring** means at least 2 distinct occurrences. A session that only
   retells another session's event is not an occurrence and is not cited. The
   count is the number of sessions with an occurrence, with no eligible-session
   denominator. Robin can't cite which sessions were eligible, so she doesn't
   claim one. She may mention it in the description when it is obvious.
4. **Evidence in chat.** Each item gives a one-sentence description and up to 3
   citations, `<bead title> session <id8>: "<one-line verbatim quote>"`, then
   `+N more`. The human can ask to see the rest.
5. **Evidence in the Signal.** The Sources line cites every session with an
   occurrence, and the body quotes the 2 strongest lines.
6. **Tails, unnumbered.** `Seen once:` lists one-off findings, one line each
   with their single citation. `Already on the graph:` names each pattern that
   matches an open bead, with that bead's title. Robin numbers a tail item only
   when the human asks for it to be filed.
7. **Overlaps.** Robin merges clear duplicates herself (same cause, same fix)
   before she presents the list, and marks near-duplicates with `overlaps M`.
8. **Answering.** The human answers in free form ("yes 1, 3", "all but 4",
   "merge 2 5"). Robin reads back the Signals she will draft before she drafts
   any. Each yes drafts one Signal, and a merge drafts one Signal for the merged
   patterns.

## Considered Options

- **Headings per kind.** Rejected: the headings break up the numbering the
  human answers by, and the kind changes nothing after triage.
- **A denominator of eligible sessions** ("6 of 7 Build/Critique sessions").
  Rejected: which sessions were eligible is Robin's judgement and can't be
  cited.
- **Dropping one-offs silently.** Rejected: a single occurrence can still
  matter. The tail keeps it visible without offering it as a pattern.
