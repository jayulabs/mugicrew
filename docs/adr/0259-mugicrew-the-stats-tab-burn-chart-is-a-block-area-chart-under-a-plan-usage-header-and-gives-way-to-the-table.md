# The Stats tab burn chart is a block area chart under a Plan usage header, and gives way to the table

Placement and short-height rules are amended by ADR 0297 (mugicrew-the-stats-tab-flows-usage-sessions-distribution…) and ADR 0298 (mugicrew-the-stats-flow-sizes-sessions-to-its-natural-width…).

The Stats tab charts % used over the current Plan usage window as an area chart of eighth-block runes (` ▁▂▃▄▅▆▇█`), 6 rows tall plus a 3-row x axis, settled by prototype (bead "Burn chart rendering and layout in the Stats tab", throwaway on `refs/mugicrew/prototypes/mc-85c0.5`). The tab splits into two sections under bold accent headers, **Plan usage** (the usage band, then the chart) and **Sessions** (the window/grouping line, then the table), with a blank line between them when stacked. When the pane is at least 110 columns (table 72 + chart 36 + 2), the sections sit side by side, Sessions left and Plan usage right; narrower, Plan usage stacks above Sessions.

- **Axis scaled to the window:** x runs window start → reset, with a tick per hour (5h: `0h…5h`) or per day (wk: `0d…7d`), `▲` at now, and a line `▲ <in> in · <left> left · resets <Mon 15:04>`; the rest of the window to come is a dim `┄` baseline. y gutter `100┤`, ` 50┤` (from 5 rows), `  0┤`.
- **Bucketing:** a column's value is the highest % read inside its time slice, else the last read before it if that read is no more than 10m older (2 × the TUI poller's 300s tick), else the column is a gap.
- **Gaps** (no TUI running) render as dim `░` hatching, full height.
- **Near-duplicates** from two TUIs are dropped at read: reads sorted by time, any read less than 60s after the last kept one is skipped.
- **Colour:** muted orange (256-colour 180), turning amber at 80% used and red at 95%, the same thresholds as the tab-bar warning (`usageWarnPct`/`usageErrPct`). The live orange (214) was rejected because it is the 80% warn colour, so the warning would disappear.
- **`u` cycles the limit window 5h ↔ wk** (bead "Which key cycles the burn chart between 5h and wk"). `w` already cycles the stats window, and `W` would put two different "windows" on one letter. `u` matches the Plan usage header and is free on Stats since ADR 0241 (…n-opens-a-shell-wide-new-menu…) removed Graph's `u` (History's `u undo` is a different tab's key; Graph's `U` unblock is untouched). Hint `u 5h/wk` sits in the bar's tab section, ranked with the tab extras (ADR 0229 (…hints-bar-and-key-reference…) §3). The chart always opens on 5h and does not persist, the same as `w`'s fixed 7d default. Opening on whichever window is nearer its limit was rejected because the opening view would change between launches.
- **Which window, and reads across a reset** (bead "How the burn chart reads when a window's reset time is unknown or reads straddle a reset"). The latest read's reset defines the window for every read. If that reset is unknown (zero), the chart uses the newest earlier read's reset that is still in the future. When the endpoint omits a reset, it usually means no window is running, so a blip between known resets should not blank the chart. With no future reset known, the chart is replaced by a dim `(no 5h window running)` (or `wk`). With only a passed reset known (now ≥ reset), it is replaced by a dim `(5h window reset)`, matching the band's `5h reset`. It returns on the next good read. Only reads timed in [start, reset) are plotted. A read whose own reset is at or before the window start belongs to the previous window and is dropped, so the % fall at rollover never shows. Rejected: anchoring the axis on now − window length, because it breaks the start → reset axis. Per-read exact reset matching was also rejected, because the server's reset jitters between reads.
- **Short heights:** Sessions rows go last; the chart shrinks to fit and is replaced by a dim `(chart hidden: too short)` below 2 rows.

## Considered Options

- Braille line chart (finer, but thin and harder to read as "how full").
- One-row sparkline folded into the usage band (no extra rows, but no axis, so you cannot see how far into the window you are).
